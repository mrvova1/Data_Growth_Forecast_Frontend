# Лабораторная работа №5 — React SPA

**Тема:** «Прогноз роста объёма данных»
**Стек:** React 19, TypeScript, Vite, React-Bootstrap, React Router.
**Режим лабораторной:** гостевой интерфейс; данные карточек загружаются только из локальной mock-коллекции. Бэкенд для работы приложения не требуется.

## 1. Запуск

Требуется Node.js 20.19+ или 22.x и npm.

```bash
npm install
npm run dev
```

Открыть `http://localhost:3000`.

Проверка production-сборки:

```bash
npm run build
npm run preview
```

## 2. Страницы приложения

### 2.1. Лента — `/feed`

Гостевая лента показывает по одной услуге за раз в вертикальной карточке с видео 9:16.

Элементы страницы:

- видеоблок с постером-изображением;
- тема услуги, название, краткое описание и число лайков;
- кнопка «Читать далее» / «Скрыть» для раскрытия описания;
- показатели «Рост» и «Влияние»;
- кнопка «Подробнее об услуге» для перехода на экран выбранной записи;
- кнопка «Следующая» для перехода к следующей записи mock-коллекции с циклическим возвратом к первой.

При отсутствии видео используется `public/assets/default-service-video.mp4`, а при отсутствии постера — `public/assets/default-service-image.png`.

### 2.2. Плитка — `/tile`

Страница выводит услуги в две колонки. Над списком находится форма фильтров.

Поля и кнопки:

- **Название** — поиск по подстроке в `growth_factor_name`;
- **Тема** — фильтр по `category`;
- **Дата от** — оставить услуги, созданные в эту дату или позднее;
- **Рост от** — минимальное значение `growth_coefficient`;
- **Сортировка** — новые/старые, по названию или коэффициенту роста;
- **Сбросить** — очистить фильтры и вернуть сортировку «Сначала новые».

На карточке отображаются изображение, тема, дата, количество лайков, название, коэффициент роста и влияние на хранение. Нажатие на карточку открывает страницу подробностей.

### 2.3. Просмотр услуги — `/service/:id`

Третья страница открывается из ленты или карточки плитки. Она показывает название, видео, тему, коэффициенты, число лайков, описание и дату создания.

Кнопки:

- **Назад** — вернуться на предыдущий экран;
- **Вернуться к плитке** — перейти на `/tile`.

Если видео отсутствует, экран использует локальный видеофайл-заглушку. Если видеофайл не загрузился, вместо него показывается изображение по умолчанию.

## 3. Нижняя навигация

Панель закреплена снизу и содержит четыре пункта:

| Пункт | Состояние | Назначение |
|---|---|---|
| Лента | доступен | переход на `/feed` |
| Добавление | отключён | гостю создание услуги недоступно в рамках этой лабораторной |
| Плитка | доступен | переход на `/tile` |
| Вход | отключён | авторизация не реализуется в гостевом режиме ЛР5 |

Активная вкладка подсвечивается с учётом текущего URL. На странице подробностей активной считается вкладка «Плитка».

## 4. Mock-данные и Network

Коллекция находится в `public/mock/services.json`. Она содержит 6 опубликованных услуг с полями и дополнительным mock-полем `category` для тематического фильтра.

При запуске `useServices` выполняется запрос:

```http
GET /mock/services.json
```

После изменения фильтров дополнительных запросов нет: фильтрация выполняется в браузере по уже загруженному массиву mock-объектов.

## 5. Изображение и видео по умолчанию

Файлы находятся в `public/assets/`:

- `default-service-image.png` — локальное изображение-заглушка;
- `default-service-video.mp4` — локальный пятисекундный ролик-заглушка.

Логика централизована в `src/utils/media.ts`:

- пустая строка, `null` или `undefined` в `image_url` заменяется на `DEFAULT_IMAGE`;
- пустая строка, `null` или `undefined` в `video_url` заменяется на `DEFAULT_VIDEO`;
- `onError` у изображения повторно назначает локальную картинку, если указанный в mock путь не существует;
- если видео не воспроизводится на странице подробностей, React показывает изображение-заглушку.

В mock-коллекции специально оставлены пустые `image_url` и `video_url` у нескольких записей — это позволяет показать обе ветки fallback на защите.

## 6. Компоненты, props и хуки

### Компоненты и передаваемые props

| Компонент | Props | Назначение |
|---|---|---|
| `AppLayout` | `children: ReactNode` | общий мобильный экран, шапка и нижняя навигация |
| `FeedPage` | `services`, `loading`, `error`, `onRetry` | отображение ленты, следующей записи и ошибки загрузки |
| `TilePage` | `services`, `loading`, `error` | фильтрация и отображение списка |
| `ServiceCard` | `service: Service` | карточка одной услуги |
| `ServiceFilters` | значения фильтров, список тем, callback-функции изменения и сброса | контролируемая форма фильтров |
| `ServiceDetailsPage` | `services`, `loading` | поиск услуги по `id` из URL и показ подробностей |
| `BottomNav` | нет | навигация между двумя доступными разделами |

**Как передаются props фильтрации:** `TilePage` хранит значения полей в `useState` и передаёт их в `ServiceFilters` вместе с обработчиками `setSearch`, `setCategory`, `setFromDate`, `setMinGrowth`, `setSortBy`. `ServiceFilters` не изменяет данные напрямую — он вызывает переданные функции. `TilePage` получает новые значения состояния и пересчитывает массив отображения через `useMemo`.

**Как передаются props карточки:** `TilePage` передаёт в `ServiceCard` объект `service`. Карточка читает его поля и не изменяет объект. Навигация на подробности формируется по `service.id`.

### Используемые React и Router hooks

- `useState` — состояние загрузки и mock-данных в `useServices`; состояние индекса и раскрытого описания в `FeedPage`; состояние полей фильтрации в `TilePage`; состояние ошибки видео в `ServiceDetailsPage`.
- `useEffect` — загрузка `services.json` после монтирования. В cleanup-функции вызывается `AbortController.abort()`, чтобы отменить незавершённый запрос при размонтировании.
- `useCallback` — мемоизация функции загрузки mock-данных и обработчика перехода к следующей услуге.
- `useMemo` — вычисление тем и отфильтрованного/отсортированного массива услуг без повторного расчёта при каждом рендере.
- `useLocation` — определение активного пункта нижней навигации по текущему адресу.
- `useNavigate` — программный переход к следующей услуге, списку и предыдущему экрану.
- `useParams` — чтение параметра `id` из маршрута `/service/:id`.

`useContext`, Context API и Redux в проекте не используются. Данные между страницами передаются обычными props от `App`.

## 8. Контрольные вопросы

**1. Что такое React?**
React — JavaScript-библиотека для декларативного построения пользовательских интерфейсов из компонентов. Разработчик описывает состояние и желаемую разметку, а React обновляет DOM при изменении данных.

**2. Что такое props и state?**
Props — входные данные компонента, которые передаёт родитель; дочерний компонент рассматривает их как доступные только для чтения. State — внутреннее изменяемое состояние компонента. Изменение state через setter вызывает повторный рендер.

**3. Чем компонент отличается от элемента?**
Компонент — функция или класс, описывающие повторно используемую часть интерфейса. React-элемент — описание конкретного узла интерфейса, например `<ServiceCard service={item} />`, которое React использует при построении дерева отображения.

**4. Для чего нужны `useState` и `useEffect`?**
`useState` хранит локальное состояние и возвращает текущее значение с функцией обновления. `useEffect` запускает побочные действия после рендера: загрузку данных, подписки, синхронизацию с внешними системами. Функция возврата из эффекта очищает ресурс.

**5. Что такое жизненный цикл компонента?**
Основные этапы: монтирование (первое появление), обновление (повторный рендер при изменении props/state) и размонтирование (удаление из дерева). В функциональных компонентах побочные действия и очистка обычно оформляются через `useEffect`.

**6. Что такое Vite и Babel?**
Vite предоставляет dev-сервер, быструю перезагрузку модулей и production-сборку. В этом проекте Vite использует TypeScript/JSX-трансформацию и React-плагин. Babel — инструмент преобразования JavaScript/JSX и подключаемых языковых возможностей; он не заменяет проверку типов TypeScript. Проверку типов проекта выполняет `tsc` в команде `npm run build`.
